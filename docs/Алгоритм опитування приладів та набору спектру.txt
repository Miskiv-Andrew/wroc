9. АЛГОРИТМ ОПИТУВАННЯ ПРИЛАДІВ ТА НАБОРУ СПЕКТРУ
==================================================

9.1. ЗАГАЛЬНА СТРУКТУРА ОПИТУВАННЯ
-----------------------------------
Опитування виконується в окремому потоці (DeviceManager) з використанням QTimer.
Циклічний процес: один прилад → відповідь → пауза → наступний прилад.

9.2. ПАРАМЕТРИ ОПИТУВАННЯ
-------------------------
| Параметр | Значення | Опис |
|----------|----------|------|
| short_interval_ms | 3000 мс | Пауза між приладами |
| long_interval_ms | 20000 мс | Пауза між циклами (всі прилади опитані) |
| timeout_interval_ms | 3000 мс | Таймаут очікування відповіді |
| max_retries | 3 | Максимум невідповідей до помилки |

9.3. АЛГОРИТМ ЦИКЛУ ОПИТУВАННЯ (dispatch_poll_step)
----------------------------------------------------
1. Якщо список приладів порожній → зупинка таймера, вихід
2. Збільшення current_index
3. Якщо current_index >= кількості приладів:
   - Скидання current_index = -1
   - Запуск long_interval_ms (пауза між циклами)
   - Вихід
4. Отримання поточного приладу: device = devices[current_index]
5. Якщо device.is_active == False або device.is_online == False → пропуск
6. Визначення типу запиту:
   - Кожний 10-й запит (температура) → request_type = "temperature"
   - Інакше → request_type = None (ПАЕД або спектр)
7. Формування команди (make_request)
8. Відправка через COM-порт
9. Запуск таймера очікування відповіді (error_timer)

9.4. ВИЗНАЧЕННЯ ТИПУ ЗАПИТУ (make_request)
-------------------------------------------
Залежить від location_type та стану приладу.

Для room (настінний детектор):
- Завжди COMMAND_RAD_DOSE

Для cistern (цистерна):
- Якщо real_sensor == "G" → COMMAND_RAD_DOSE
- Якщо real_sensor == "S":
  * Цистерна не повна (full == False) → COMMAND_RAD_DOSE
  * Цистерна повна (full == True):
    - Спектр не активний:
      - last_paed <= 30 → COMMAND_START_SIMPLE_SPECTRE
      - last_paed > 30 → COMMAND_RAD_DOSE
    - Спектр активний → COMMAND_GET_SIMPLE_SPECTRE

9.5. ОБРОБКА ВІДПОВІДЕЙ (handle_ready_read)
-------------------------------------------
1. Додавання отриманих байтів до rx_buffer
2. Пошук заголовка пакета (0x55, 0xAA)
3. Перевірка довжини пакета (відповідно до команди)
4. Перевірка CRC
5. Зупинка таймера очікування (error_timer)
6. Скидання no_answer_count та встановлення is_online = True
7. Визначення режиму (RadDose, Temperature, StartSpectre, GetSpectre)
8. Парсинг даних відповідно до режиму
9. Відправка сигналу device_response

9.6. ОБРОБКА ТАЙМАУТУ (handle_timeout_error)
--------------------------------------------
1. Збільшення no_answer_count
2. Якщо no_answer_count >= 5:
   - Встановлення is_online = False
   - Сигнал device_missing
3. Закриття COM-порту
4. Сигнал device_error
5. Системна подія connection_error

9.7. АЛГОРИТМ НАБОРУ СПЕКТРУ
----------------------------
Процес для цистерни з real_sensor == "S", full == True, last_paed <= 30.

Етап 1: Запуск спектру
----------------------
1. Відправка COMMAND_START_SIMPLE_SPECTRE
2. Прилад починає накопичувати спектр (1024 канали)
3. Перевірка байта відповіді (res_byte):
   - 1 → успіх, spectrum_active = True
   - 0 → невдача, збільшення лічильника start_spectre_retries
4. При 3 невдалих спробах:
   - spectrum_active = False
   - Системна подія start_spectre_failed

Етап 2: Накопичення спектру
---------------------------
1. Кожні 3 секунди відправка COMMAND_GET_SIMPLE_SPECTRE
2. Отримання 2076 байт (1024 канали × 2 байти + службові дані)
3. Парсинг (_parse_spectrum_data):
   - channels[1024] — масив каналів (little-endian, 2 байти на канал)
   - paed_value — ПАЕД з пакета
   - valid — валідність результату
4. Додавання до спектру в DeviceInfo: spectrum_buffer[i] += channels[i]
5. Збільшення spectrum_counter
6. Сигнал для оновлення графіку спектру

Етап 3: Завершення набору
-------------------------
1. Коли spectrum_counter >= 600 (~30 хвилин):
   - Виклик calculate_activity() в DeviceCardBarrel
   - Розрахунок активності: total_counts / 600 / 1000 (кБк) — заглушка
   - Збереження в БД (measurements_cistern)
   - Скидання spectrum_buffer та spectrum_counter
   - Запис події spectrum_reset

9.8. ПАРСИНГ ДАНИХ
------------------
ПАЕД (COMMAND_RAD_DOSE):
- 4 байти (little-endian) → значення ПАЕД
- Коефіцієнт: 0.01 або 0.1 (залежить від біта 7 байта 10)
- Статуси детекторів з байта 10:
  * Біт 0 → високочутливий детектор (0=норма, 1=відмова)
  * Біт 1 → низькочутливий детектор (0=норма, 1=відмова)
  * Біт 2 → валідність (0=невалідний, 1=валідний)

Температура (COMMAND_TEMP):
- 12 біт зі знаком, поділити на 16 → значення в °C

Спектр (COMMAND_GET_SIMPLE_SPECTRE):
- 1024 канали × 2 байти = 2048 байт (починаючи з байта 6)
- 4 байти ПАЕД (байти 2056-2059)
- 1 байт тестовий (байт 2061) — статуси детекторів

9.9. БУФЕРИЗАЦІЯ НАСТІННИХ ДЕТЕКТОРІВ
---------------------------------------
- Кожне вимірювання додається в буфер DatabaseManager.wall_buffer
- Буфер зберігає ТІЛЬКИ ОСТАННЄ значення для кожного device_id
- Кожні 30 хвилин буфер скидається в таблицю measurements_wall
- Після скидання буфер очищується

9.10. СХЕМА ПОТОКІВ ДАНИХ
-------------------------
Прилад → COM-порт → DeviceManager (потік) → сигнал device_response → App (головний потік)
  ↓
App.on_device_packet → парсинг → оновлення GUI
  ↓
DatabaseManager.buffer_wall_measurement (настінні)
DatabaseManager.save_cistern_measurement (цистерни)

9.11. ПРИКЛАД ЧАСОВИХ ІНТЕРВАЛІВ
--------------------------------
- Один цикл опитування 3-х приладів: 3 × 3 сек = 9 сек
- Пауза між циклами: 20 сек
- Отримання температури: кожні 10 циклів (~90 сек)
- Накопичення 600 спектрів: 600 × 3 сек = 30 хвилин
- Скидання буфера настінних: 30 хвилин

9.12. ОБРОБКА ПОМИЛОК
--------------------
| Помилка | Дія |
|---------|-----|
| CRC не збігається | Сигнал crc_error, пакет відкидається |
| Таймаут (3 сек) | Збільшення no_answer_count |
| 5 таймаутів поспіль | is_online = False, сигнал device_missing |
| Невдалий запуск спектру | 3 спроби, потім start_spectre_failed |
| COM-порт не відкривається | Сигнал device_error, перехід до наступного приладу |
