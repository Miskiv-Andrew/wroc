Формат конфігураційних файлів
Директорія: config/

4.1 config.txt — основна конфігурація приладів
Формат: serial_number;location_type;position_number;address

Поле	Тип	Опис	Приклад
serial_number	string	Серійний номер приладу	2400089
location_type	string	Тип розташування: cistern / room	cistern
position_number	int	Номер цистерни або кімнати	1
address	int	Адреса приладу в шині RPII (1-6)	1
Приклад файлу:

text
# serial_number;location_type;position_number;address
2400089;cistern;1;1
2400126;room;1;2
2400127;room;2;3
2400128;room;3;4
Правила:

Рядки, що починаються з # — коментарі (ігноруються)

Порожні рядки ігноруються

Кожен прилад має унікальний serial_number

Адреси можуть повторюватися? Ні, кожен прилад на одному порту RPII має унікальну адресу

Створення:

Автоматично при першому запуску з debug_mode = 1

Оновлюється при заміні приладу

4.2 hash.txt — контрольна сума config.txt
Формат: SHA-256 хеш (64 символи в шістнадцятковому форматі)

Приклад:

text
3cd9232df699687ff2f7a8647c6743fa03d2d3339886c8f7406030c3ad22ae21
Призначення:

Перевірка цілісності config.txt

При невідповідності хеша програма блокує роботу та виводить помилку

Захист від випадкового або навмисного пошкодження конфігурації

Оновлення:

Кожного разу при зміні config.txt автоматично перераховується хеш

Використовується алгоритм SHA-256

4.3 cistern.json — стан заповненості цистерн
Формат: JSON об'єкт, де ключ — номер цистерни (string), значення — стан (boolean)

Приклад:

json
{
    "1": false,
    "2": true,
    "3": false
}
Значення:

true — цистерна повна

false — цистерна порожня

Призначення:

Зберігає стан заповненості цистерн, отриманий від зовнішньої системи управління (HMI)

Впливає на режим роботи програми:

Цистерна не повна → запит ПАЕД

Цистерна повна, ПАЕД ≤ 30 → запуск спектру

Цистерна повна, ПАЕД > 30 → тільки ПАЕД

Оновлення:

Програма читає файл кожні 30 секунд (або при зміні через сигнал від ВСУ)

При зміні стану:

Оновлюється DeviceInfo.full для відповідного приладу

Скидається спектр (якщо цистерна стала порожньою)

Запускається нове накопичення (якщо цистерна стала повною)

Створення:

Автоматично при першому запуску з debug_mode = 1 (всі цистерни → false)

При заміні приладу цистерни — копіює стан для нової позиції

Взаємозв'язок файлів
text
config.txt  ←───────────→  hash.txt
    │                         (SHA-256)
    │
    ↓
cistern.json  (незалежний, тільки стан заповненості)
Синхронізація з БД:

config.txt → містить SN, тип, позицію, адресу

devices таблиця в БД → містить SN, тип, позицію, is_active

При заміні приладу оновлюються обидва джерела
