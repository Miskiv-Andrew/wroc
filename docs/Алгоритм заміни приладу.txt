7. АЛГОРИТМ ЗАМІНИ ПРИЛАДУ
===========================

7.1. ПРИЗНАЧЕННЯ
----------------
Заміна фізично несправного приладу на новий без зміни конфігурації системи
(адреса, тип розташування, номер позиції залишаються тими ж).

7.2. УМОВИ ДЛЯ ЗАМІНИ
---------------------
- Новий прилад має адресу 200 або 201 (заводське налаштування)
- Старий прилад може бути як активним (is_active=1), так і неактивним (is_active=0)
- Новий прилад не повинен існувати в БД (серійний номер унікальний)

7.3. АЛГОРИТМ РОБОТИ
--------------------

Етап 1: Підготовка
------------------
1. Адміністратор фізично відключає старий прилад
2. Підключає новий прилад (адреса 200 або 201)
3. Запускає програму (якщо не запущена)
4. Відкриває меню «Прилади» → «Заміна приладу»

Етап 2: Пошук нового приладу
----------------------------
1. У діалозі заміни адміністратор натискає «Знайти новий прилад»
2. AddressChanger.scan_new_device() виконує:
   - Пошук доступних COM-портів (FTDI/RPII)
   - Опитування адрес 200 та 201 командою COMMAND_SER_NUM
   - Отримання серійного номера нового приладу
3. При успіху:
   - Поле «Новий SN» заповнюється автоматично
   - Кнопка «Виконати заміну» стає активною
4. При невдачі:
   - Виводиться повідомлення «Новий прилад не знайдено»

Етап 3: Вибір старого приладу
-----------------------------
1. Адміністратор обирає старий прилад з випадаючого списку
2. Список містить всі активні прилади (is_active=1)
3. Автоматично відображається розташування старого приладу

Етап 4: Перевірки
-----------------
1. Перевірка на однакові SN (старий == новий)
   - Якщо так → помилка «Однакові SN», заміна неможлива
2. Перевірка наявності старого приладу в config.txt
   - Якщо ні → помилка, заміна неможлива
3. Отримання з config.txt:
   - location_type
   - position_number
   - target_address (адреса, яку потрібно встановити)

Етап 5: Зміна адреси нового приладу
-----------------------------------
1. AddressChanger.change_address(port, old_addr, target_address, new_sn)
   - Відправка команди зміни адреси (200/201 → target_address)
   - Очікування відповіді (таймаут 1 сек, 3 спроби)
   - Перевірка CRC та старого адресу у відповіді
2. При успіху → перехід до етапу 6
3. При невдачі → виведення помилки, заміна скасовується

Етап 6: Оновлення конфігураційних файлів
----------------------------------------
1. Оновлення config.txt:
   - Заміна старого SN на новий (в тій самій стрічці)
   - Адреса, тип розташування, номер позиції не змінюються
2. Перерахунок hash.txt (SHA-256 від config.txt)
3. Оновлення cistern.json:
   - Якщо location_type == "cistern" — копіювання стану заповненості
   - Якщо немає запису для позиції — створення з false

Етап 7: Оновлення бази даних
----------------------------
1. Старий прилад: UPDATE devices SET is_active = 0 WHERE serial_number = old_sn
2. Новий прилад: INSERT INTO devices (serial_number, device_type, location_type, position_number, is_active)
   VALUES (new_sn, 'БДБГ-09S-23', location_type, position_number, 1)
3. Запис події: INSERT INTO system_events (device_id, timestamp, event_type, description)
   VALUES (NULL, datetime('now'), 'device_replaced', 'Заміна приладу: old_sn -> new_sn, позиція X')
4. Оновлення кешу активних приладів: reload_devices_map()

Етап 8: Завершення
------------------
1. Виведення повідомлення: «Заміна виконана. Необхідно перезапустити програму»
2. Адміністратор закриває програму та запускає знову
3. Новий прилад з'являється в списку активних

7.4. ОБРОБКА ПОМИЛОК
--------------------
| Помилка | Дія |
|---------|-----|
| Новий прилад не знайдено | Повідомлення, кнопка «Виконати заміну» неактивна |
| Однакові SN | Повідомлення, заміна скасовується |
| Помилка зміни адреси (3 спроби) | Повідомлення, заміна скасовується |
| Старий SN не знайдено в config.txt | Повідомлення, заміна скасовується |

7.5. БЛОКУВАННЯ ПІД ЧАС ЗАМІНИ
-------------------------------
- Під час пошуку нового приладу: кнопки «Знайти новий прилад» блокуються
- Під час зміни адреси: кнопка «Виконати заміну» блокується
- Після завершення (успіх або помилка) — розблокування

7.6. ВІДМІННОСТІ ВІД АКТИВАЦІЇ ПРИЛАДУ
--------------------------------------
| Характеристика | Заміна | Активація |
|----------------|--------|-----------|
| Зміна SN | Так (старий → новий) | Ні |
| Зміна адреси | Так (200/201 → цільова) | Ні |
| Зміна is_active | Старий = 0, новий = 1 | 0 → 1 |
| Потрібен фізичний прилад | Так (адреса 200-201) | Ні |
| Використовує AddressChanger | Так | Ні |

7.7. ПРИКЛАД ВИКОРИСТАННЯ
--------------------------
Вхідні дані:
- Старий прилад: SN=2400089, адреса=1, цистерна №1
- Новий прилад: SN=2400123, адреса=200

Дії:
1. Пошук нового приладу → знайдено SN=2400123
2. Вибір старого приладу → 2400089
3. Виконати заміну → зміна адреси 200→1
4. Оновлення config.txt: 2400089 → 2400123
5. БД: 2400089.is_active=0, 2400123.is_active=1

Результат:
- Новий прилад працює на адресі 1 замість старого
- Система продовжує опитування без зміни налаштувань
