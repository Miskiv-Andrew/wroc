5.1 app.py — головний модуль

Головний клас програми. Відповідає за GUI, управління картками приладів, синхронізацію з БД та потоками.

Основні атрибути:

Атрибут	Тип	Опис
ui	QMainWindow	Завантажений інтерфейс з main_window_form.ui
device_manager	DeviceManager	Менеджер опитування приладів (в окремому потоці)
device_manager_thread	QThread	Потік для DeviceManager
db_manager	DatabaseManager	Робота з БД
cards_by_sn	dict	Словник карток приладів {serial_number: widget}
cistern_dict	dict	Стан заповненості цистерн {номер: True/False}
Основні методи:

Метод	Опис
load_ui()	Завантаження головного вікна з _UI/main_window_form.ui
setup_connections()	Підключення сигналів та слотів
setup_device_manager()	Створення потоку та DeviceManager

on_device_packet(packet)	Обробка даних від приладів (ПАЕД, температура, спектр)
on_device_missing(serial_number)	Активація пункту меню заміни приладу
open_replace_dialog()	Відкриття діалогу заміни/активації приладів
stop_system()	Зупинка опитування
cleanup()	Коректне завершення програми

5.2 device_manager.py — управління опитуванням приладів
Клас DeviceManager (QObject)

Працює в окремому потоці. Відповідає за опитування приладів через COM-порт, парсинг даних, контроль таймаутів.

Основні атрибути:

Атрибут	Тип	Опис
devices	list[DeviceInfo]	Список приладів для опитування
serial_port	QSerialPort	COM-порт для зв'язку
poll_timer	QTimer	Таймер опитування
error_timer	QTimer	Таймер очікування відповіді
current_index	int	Індекс поточного приладу
last_command	Command	Остання відправлена команда
debug_mode	int/None	Режим налагодження (1 або None)
Основні методи:

Метод	Опис
find_rpii_ports()	Пошук COM-портів з FTDI/RPII
scan_devices()	Опитування адрес 1-6 для пошуку приладів
match_devices_with_config()	Зіставлення знайдених приладів з config.txt
dispatch_poll_step()	Циклічне опитування приладів
make_request()	Формування запиту до приладу
handle_ready_read()	Обробка вхідних даних від приладу
handle_timeout_error()	Обробка таймауту (немає відповіді)
calc_crc()	Розрахунок CRC
verify_crc()	Перевірка CRC
_paed_data()	Парсинг ПАЕД
_temp_data()	Парсинг температури
_parse_spectrum_data()	Парсинг спектру (1024 канали)
Сигнали:

Сигнал	Опис
device_found	Список знайдених приладів
device_response	Отримані дані від приладу
device_error	Помилка (CRC, таймаут, конфіг)
device_connection_status	Статус зв'язку
device_missing	Прилад не відповідає 5 циклів
system_event	Системна подія

5.5 address_changer.py — заміна адреси приладу
Клас AddressChanger (QObject)

Відповідає за пошук нового приладу на адресах 200-201 та зміну його адреси на цільову (з config.txt).

Атрибути:

Атрибут	Тип	Опис
device_manager	DeviceManager	Для використання calc_crc() та verify_crc()
Методи:

Метод	Опис
find_new_device(addresses=[200, 201])	Пошук приладу на адресах 200-201, отримання SN
change_address(port, old_addr, new_addr, expected_sn)	Зміна адреси приладу (3 спроби, таймаут 1 сек)
_get_available_ports()	Пошук COM-портів FTDI/RPII
_extract_serial_number(data)	Отримання SN з відповіді
Сигнали:

Сигнал	Опис
found	Знайдено новий прилад (port, SN, address)
status	Текстове повідомлення про статус
error	Повідомлення про помилку
Протокол зміни адреси:

Команда: [0x55, 0xAA, 0x70, OLD_ADDR, 0x06, NEW_ADDR, 0x00] + CRC

Відповідь: [0x55, 0xAA, 0x70, OLD_ADDR, 0x06, STATUS, CRC] (6 байт + CRC)

Успіх: перевірка CRC та збіг OLD_ADDR

Таймаут: 1 секунда, повторів: 3

App (головний потік)
    │
    ├── створює ──→ DatabaseManager
    ├── створює ──→ DeviceManager (в окремому потоці)
    │                   │
    │                   ├── використовує ──→ DeviceInfo
    │                   ├── створює ──→ AddressChanger (при заміні)
    │                   └── викликає ──→ DatabaseManager (потокобезпечні методи)
    │
    ├── отримує сигнали ←── DeviceManager
    │
    └── створює ──→ DeviceCardBarrel / DeviceCardWall (GUI)
